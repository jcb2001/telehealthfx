## 1. Executive Summary & GSC Generative AI Dataset Forensic Audit

### 1.1 The Generative Search Shift in Telemedicine
The emergence of Retrieval-Augmented Generation (RAG) engines—specifically **Google Gemini / AI Overviews (formerly SGE)**, **Perplexity AI (Sonar / Pro Search)**, and **OpenAI ChatGPT Search (SearchGPT)**—has precipitated the most significant architectural paradigm shift in digital healthcare search since the introduction of mobile-first indexing. 

In legacy search engine results pages (SERPs), discovery was mediated through the "ten blue links" model: users executed keyword queries, scanned meta titles and snippets, and clicked through to host websites to extract clinical answers. In contemporary generative search environments, Large Language Models (LLMs) synthesize clinical answers directly on the search interface. The LLM retrieves candidate web passages, evaluates clinical consensus, extracts factual data points and regulatory determinations, and compiles a comprehensive direct answer—frequently satisfying the user's primary informational intent without requiring a website click.

For `telehealthfx.com`, this shift presents both a profound vulnerability and an unprecedented commercial growth opportunity:
- **The Zero-Click Threat**: Informational content written in legacy narrative prose is ingested by LLMs to answer patient queries without providing a prominent, clickable attribution link, reducing organic click-through rates (CTR).
- **The High-Intent Verification Opportunity**: Users who *do* click through from generative answers represent a fundamentally different cohort than traditional searchers. Having already consumed the factual answer, they arrive with **verification intent** and **transactional readiness**. They click to verify clinical legitimacy, pricing transparency, and delivery speeds, and to initiate medical intake immediately.
- **Topical Authority Imperative**: Generative engines apply rigorous **Your Money or Your Life (YMYL)** filtering. Winning AI citations requires authoritative clinical consensus citations (e.g., Section 503A of the FD&C Act, TSA Title 49 CFR § 1540.111, FDA Wegovy Prescribing Information) paired with dense, unambiguous numerical parameters.

   - `https://telehealthfx.com/blog/compounded-semaglutide-after-hims-ro-2026/`: 2,775 imp, 45 clicks (Position 6.98)
   - `https://www.telehealthfx.com/blog/compounded-semaglutide-after-hims-ro-2026/`: 82 imp, 1 click (Position 10.73)
   - `https://www.telehealthfx.com/blog/compounded-semaglutide-after-hims-ro-2026`: 67 imp, 1 click (Position 12.03)
   - *Impact*: 149 search impressions and 2 high-intent clicks were siphoned into duplicate non-canonical entities. More critically, LLM web indexers (such as Google-Extended, PerplexityBot, and OAI-SearchBot) crawl these variations independently, splitting entity trust scores and diluting citation confidence.
2. **The Results Page Ranking Inversion**:
   - `https://telehealthfx.com/results/`: 105 imp, 1 click (Position 22.56)

   - *Impact*: The non-canonical `www` version without trailing slash ranks in **Position 1.72**, while the intended canonical URL on the apex domain languishes on page 3 in **Position 22.56**. This proves that Google has indexed both hosts as competing entities.
3. **Local Metro Page Cannibalization**:
   - High-volume metro queries are split between `/locations/[metro]/` on the apex domain and `/weight-loss/[metro]/` on the `www` subdomain (e.g., Chicago: 194 imp on `www.telehealthfx.com/weight-loss/chicago/`; Miami: 179 imp on `www`; Nashville: 135 imp on `www`).
4. **Root Cause in Next.js Codebase**:
   - In `Telehealth FX Site/src/app/layout.js`, `metadataBase` is not defined, causing Next.js to generate relative or inconsistent OpenGraph and canonical headers.
   - Root layout metadata lacks an explicit `alternates: { canonical: 'https://telehealthfx.com/' }`.
   - `next.config.mjs` specifies `trailingSlash: true` and `output: 'export'`, but because this is a static export hosted on a CDN (Cloudflare Pages), the edge server was not configured with an explicit 301 redirect rule forcing `www` requests to apex.
   - Hardcoded `www.telehealthfx.com` internal links were discovered in `src/components/blog-index.jsx` and legacy sitemap generators.

Remediating this domain split is a prerequisite for GEO dominance, as LLMs penalize ambiguous canonical signals.


## 2. LLM Retrieval, Chunking & Citation Attribution Mechanics

### 2.1 End-to-End RAG Ingestion Pipeline in AI Search Engines
To engineer content that Large Language Models consistently select as authoritative citations, we must deconstruct the mechanical architecture governing how AI search engines ingest, index, rank, and synthesize web documents. 

Modern generative search engines do not read web pages like human visitors, nor do they treat a 3,000-word article as a monolithic text block. Instead, they operate via a high-velocity, five-stage **Retrieval-Augmented Generation (RAG)** pipeline:

```
[User Natural Language Prompt / Search Query]
                     │
                     ▼
┌─────────────────────────────────────────────────────────────┐
│ 1. Multi-Query Expansion & Intent Classification (YMYL)     │
│    Decomposes conversational prompts into targeted vectors  │
└────────────────────────────┬────────────────────────────────┘
                             │
                             ▼
┌─────────────────────────────────────────────────────────────┐
│ 2. Hybrid Lexical + Dense Vector Retrieval (BM25 + Dense)   │
│    Extracts top ~50 candidate documents from web index      │
└────────────────────────────┬────────────────────────────────┘
                             │
                             ▼
┌─────────────────────────────────────────────────────────────┐
│ 3. Semantic Chunking (150–300 Words) & Cross-Encoder Rank   │
│    Partitions HTML into bounded passages; scores EEAT/UMLS  │
└────────────────────────────┬────────────────────────────────┘
                             │
                             ▼
┌─────────────────────────────────────────────────────────────┐
│ 4. Attribution Grounding & Extractive Synthesis             │
│    Verifies facts against clinical graph; extracts answer   │
└────────────────────────────┬────────────────────────────────┘
                             │
                             ▼
┌─────────────────────────────────────────────────────────────┐
│ 5. Citation Placement & Anchor Link Generation              │
│    Generates inline badge, bracketed footnote [1], or deep  │
│    fragment anchor (https://site.com/doc/#:~:text=quote)    │
└─────────────────────────────────────────────────────────────┘
```

#### The Five Stages Explained:
1. **Multi-Query Expansion & Intent Classification**: The engine receives a complex conversational query (e.g., *"Did Hims stop selling compounded semaglutide and where can I buy it safely online?"*). The query is classified under **YMYL (Healthcare/Pharmacology)**, which activates higher trust thresholds. The query is expanded into multiple sub-queries targeting regulatory status, competitor policies, and licensed telemedicine alternatives.
2. **Hybrid Lexical + Dense Vector Retrieval**: The system executes both sparse lexical matching (BM25 for exact terms like *"503A"*, *"semaglutide"*, *"Hims"*) and dense semantic vector retrieval (using embedding models like ColBERT, text-embedding-3-large, or Google Gemini embeddings) across billions of web pages to retrieve a pool of ~50 candidate documents.
3. **Semantic Chunking & Cross-Encoder Reranking**: Documents are split into semantic chunks (typically 150 to 300 words), bounded by HTML structural tags (`<h2>`, `<h3>`, `<p>`, `<table>`). A heavy cross-encoder neural network scores each chunk for semantic relevance, factual density, author credibility (EEAT), and medical ontology alignment (UMLS concepts).
4. **Attribution Grounding & Synthesis**: The generative model reads the top 5 to 10 chunks within its context window. It verifies factual consistency against its internal parameters and clinical knowledge bases (FDA drug databases, PubMed, CDC). It extracts sentences that answer the user's prompt directly.
5. **Citation Placement & Anchor Link Generation**: The synthesizer assigns citation markers. If the source provides unambiguous proprietary data (e.g., specific dollar pricing, delivery timelines, regulatory statutes), the model generates a prominent, clickable citation anchor linking directly to the source page or text fragment.

### 2.2 Google Gemini & AI Overviews (SGE) Retrieval Mechanics
Google's Generative AI Features (AI Overviews) are powered by the **Gemini multimodal model family** operating directly over the Google Search index.

```
+---------------------------------------------------------------------------------------------------------------+
| GOOGLE GEMINI / AI OVERVIEWS RETRIEVAL ARCHITECTURE                                                           |
+------------------------------+--------------------------------------------------------------------------------+
| Pipeline Component           | Technical Specification & Mechanical Behavior                                  |
+------------------------------+--------------------------------------------------------------------------------+
| Web Index Ingestion          | Googlebot crawls HTML; MUM & Gemini generate dense multi-vector embeddings.   |
| Passage-Level Chunking       | Chunks are bounded by heading tags (`<h2>`, `<h3>`) and typically span 150–250 |
|                              | words. Standalone paragraphs without headings suffer chunking fragmentation.   |
| Clinical Grounding Engine    | Google's Medical Knowledge Graph (built from FDA package inserts, DailyMed,   |
|                              | UMLS, and PubMed) validates medical assertions before synthesis.               |
| YMYL Classifier Gate         | Health queries undergo strict algorithmic validation; speculative claims or   |
|                              | unsourced medical guidance are filtered out to prevent hallucinations.         |
| Primary Citation Format      | Expandable carousel cards at top of overview, inline interactive pill badges, |
|                              | and deep text fragment anchors (`#:~:text=`).                                  |
| Structural Preference        | Strong preference for bolded opening thesis sentences followed by HTML tables. |
+------------------------------+--------------------------------------------------------------------------------+
```

#### Key Architectural Requirements for Google AI Overviews:
- **Passage-Level Syntactic Bounding**: Google's chunker treats each `<h2>` and `<h3>` heading as an independent document boundary. An extractive answer must be positioned immediately beneath the heading, beginning with a bolded summary sentence that encapsulates the entire resolution in 15 to 25 words.
- **Deep Text Fragment Generation (`#:~:text=`)**: When Google AI Overviews cites a source, it increasingly appends a scroll-to-text fragment anchor to the URL. For example:
  `https://telehealthfx.com/blog/compounded-semaglutide-after-hims-ro-2026/#:~:text=Yes%2C%20patients%20can%20legally%20obtain`
  If our on-page text is formatted with distinct punctuation, clear sentence structure, and semantic uniqueness, Google's citation builder can construct this anchor without ambiguity.
- **Semantic Anchor IDs**: When answers are housed under explicit semantic IDs in the HTML (e.g., `<section id="legal-status-503a">`), Google's crawler preferentially links directly to the anchor (`/blog/.../#legal-status-503a`), providing an elevated user experience upon click-through.

```
+---------------------------------------------------------------------------------------------------------------+
| PERPLEXITY AI (SONAR / PRO SEARCH) CITATION ARCHITECTURE                                                      |
+------------------------------+--------------------------------------------------------------------------------+
| Pipeline Component           | Technical Specification & Mechanical Behavior                                  |
+------------------------------+--------------------------------------------------------------------------------+
| Query Fan-Out Pipeline       | Decomposes single user prompt into 3 to 5 distinct search queries executed     |
|                              | concurrently across web search APIs.                                           |
| Live Index Recency Bias      | Heavily prioritizes newly published or modified content with fresh ISO 8601    |

| Sentence Attribution Engine  | Evaluates every synthesized sentence; appends bracketed numerical footnotes   |

| Table & Parameter Bias       | Perplexity exhibits an overwhelming preference for tabular data. A single HTML |

```

#### The Perplexity Multi-Query Fan-Out Phenomenon:
When a user asks Perplexity: *"Can I still buy compounded semaglutide now that Hims stopped selling it?"*, Perplexity executes three distinct API searches:
1. `hims compounded semaglutide discontinued 2026`
2. `is compounded semaglutide legal after fda shortage ends 503a`
3. `best telehealth clinics for compounded semaglutide pricing`

If a single page on `telehealthfx.com` contains answers to all three sub-queries within structured subsections (compounding legality, competitor policies, and Telehealth FX pricing/delivery), **Perplexity cites Telehealth FX across all three sub-queries**, dominating the entire footnote attribution panel (`[1]`, `[2]`, `[3]`).

### 2.5 The Zero-Click Dilemma: Why LLMs Cite Unlinked Text vs Prominent Clickable Anchor Links
An alarming vulnerability in Generative Engine Optimization is the **"zero-click AI extraction"**—where an LLM digests your content to answer the user's prompt, but mentions your brand name as plain, unlinked text, or omits your brand entirely and buries the link in a secondary menu.

```
+---------------------------------------------------------------------------------------------------------------+
| UNLINKED MENTION VS CLICKABLE CITATION ANCHOR DETERMINANTS                                                    |
+---------------------------------------+-----------------------------------------------------------------------+
| Unlinked Mention / Suppressed Link    | Prominent Clickable Citation Anchor Link                              |
+---------------------------------------+-----------------------------------------------------------------------+
| Common knowledge narrative prose      | Proprietary factual data (exact pricing, SLAs, regulatory codes)      |
| Vague qualitative statements          | Direct numerical parameters ($146/mo, 24-hr approval, 2-day delivery) |
| Long rambling paragraphs (>100 words) | Syntactically isolated extractive Q&A blocks (<40 words)              |
| Ambiguous or conflicting canonicals   | Unified, authoritative apex canonical URL (`https://telehealthfx.com`)|
| Missing Schema.org semantic markup    | Rich JSON-LD `MedicalWebPage` with RxNorm and ICD-10 ontologies       |
```

```javascript
// Telehealth FX Site/tests/verify-geo-canonical-schema.js
const fs = require('fs');
const path = require('path');

function runGeoAudit() {
  console.log('Starting Telehealth FX GEO & Schema Verification Suite...');
  const outDir = path.join(__dirname, '..', 'out');
  if (!fs.existsSync(outDir)) {
    console.error('FAIL: out/ directory does not exist. Run build first.');
    process.exit(1);
  }

  const htmlFiles = [];
  function scan(dir) {
    for (const f of fs.readdirSync(dir)) {
      const p = path.join(dir, f);
      if (fs.statSync(p).isDirectory()) scan(p);
      else if (f.endsWith('.html')) htmlFiles.push(p);
    }
  }
  scan(outDir);
  console.log(`Auditing ${htmlFiles.length} static HTML routes...`);

  let wwwViolations = 0;
  let canonicalMissing = 0;
  let jsonLdErrors = 0;
  let speakableFound = 0;

  for (const file of htmlFiles) {
    const html = fs.readFileSync(file, 'utf8');

    // Gate 1: Check for www host references (excluding intentional redirect config)
    if (html.includes('https://www.telehealthfx.com')) {
      wwwViolations++;
      console.warn(`[G1 Violation] Non-canonical www found in: ${file}`);
    }

    // Gate 2: Check for canonical tag presence
    if (!html.includes('rel="canonical"')) {
      canonicalMissing++;
      console.warn(`[G2 Violation] Missing canonical tag in: ${file}`);
    }

    // Gate 3: Validate JSON-LD syntax
    const jsonLdMatches = html.match(/<script type="application\/ld\+json">([\s\S]*?)<\/script>/gi);
    if (jsonLdMatches) {
      for (const m of jsonLdMatches) {
        const rawJson = m.replace(/<script type="application\/ld\+json">/i, '').replace(/<\/script>/i, '');
        try {
          const parsed = JSON.parse(rawJson);
          if (JSON.stringify(parsed).includes('SpeakableSpecification')) {
            speakableFound++;
          }
        } catch (e) {
          jsonLdErrors++;
          console.error(`[G3 Violation] Malformed JSON-LD in ${file}:`, e.message);
        }
      }
    }
  }

  console.log('--- AUDIT RESULTS ---');
  console.log(`Total HTML files audited: ${htmlFiles.length}`);
  console.log(`WWW Host Violations: ${wwwViolations}`);
  console.log(`Missing Canonical Tags: ${canonicalMissing}`);
  console.log(`Malformed JSON-LD Scripts: ${jsonLdErrors}`);
  console.log(`SpeakableSpecification Schemas Verified: ${speakableFound}`);

  if (wwwViolations > 0 || canonicalMissing > 0 || jsonLdErrors > 0) {
    console.error('GEO Verification FAILED.');
    process.exit(1);
  }
  console.log('All GEO & Schema Verification Gates PASSED successfully.');
}

runGeoAudit();
```
